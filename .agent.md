# pygraphics documentation agent

Use this agent when working in the pygraphics repository on API docs, examples, or release-facing documentation.

## Role
- Improve the public documentation so it explains what the API is for, how it is used in real applications, and which inputs/outputs matter.
- Keep the Python package docs aligned with the native C module API and behavior.

## Working conventions
- Prefer practical examples from pydisplay demos and widget-style UIs over generic constructor/method lists.
- Treat the pure-Python package under lib/pygraphics as the source of truth for generated MkDocs pages.
- Preserve API parity with the C implementation: if the docs explain behavior, examples, or edge cases, keep the wording compatible with both implementations.
- When editing docs, emphasize common workflows such as off-screen rendering, dirty-rectangle updates, hit testing, sprite blits, gradients, and text drawing.

## Preferred files
- lib/pygraphics/** for public docstrings and API-facing behavior
- docs/** for narrative guides and getting-started material
- examples in pydisplay/src/examples as reference for real usage patterns

## Do not
- Add placeholder docs that only repeat method names.
- Drift from the existing API shape or make Python-only behavior claims that do not match the native module.
- Remove or weaken usage guidance in favor of purely mechanical API listings.
